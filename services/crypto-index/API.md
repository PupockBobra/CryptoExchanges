# Контракт API репликатора криптоиндекса

Все эндпоинты — **read-only, без авторизации, метод GET**. CORS открыт (`*`), так что
фронт трекера может ходить к API и с другого origin. Время везде — **unix-секунды UTC**;
в CSV дополнительно колонка `iso_utc`.

Базовый путь (`{BASE}`) зависит от того, как подключили сервис (см. INTEGRATION.md):
- за reverse-proxy: `https://<домен-трекера>/crypto-index`
- напрямую к сервису: `http://<ip>:8787`

---

## GET `{BASE}/api/latest`
Последнее рассчитанное значение индекса по всем монетам (обновляется каждые 15с).

**Ответ (JSON):**
```json
{
  "ts": 1785242670,
  "iso": "2026-07-28T12:44:30Z",
  "weights": { "binance": 0.5, "bybit": 0.2, "okx": 0.15, "bitget": 0.15 },
  "coins": [
    {
      "coin": "BTC",
      "index": 63470.28325,      // итоговый индекс (взвешенное среднее)
      "n_exchanges": 4,          // сколько бирж участвовало (при пропуске < 4)
      "binance": 63470.255,      // минутное среднее по бирже
      "bybit": 63468.9,
      "okx": 63470.3,
      "bitget": 63472.205,
      "min_samples": 4,          // мин. число сэмплов в окне по биржам (4 = полная минута)
      "missing_now": [],         // биржи без свежей цены на этом такте
      "flag": "ok"               // качество такта (см. легенду ниже)
    }
    // ... ETH, SOL, TRX, XRP
  ]
}
```
Если данных ещё нет: `{"ts": null, "iso": null, "weights": {...}, "coins": []}`.

Порядок монет всегда: BTC, ETH, SOL, TRX, XRP.

**Легенда `flag` (контроль качества — по нему видно, что расчёт корректен):**
| flag | смысл |
|---|---|
| `ok` | все 4 биржи, полное окно из 4 сэмплов, свежая цена на этом такте — индекс строго по методике |
| `PARTIAL_WINDOW` | окно ещё неполное (<4 сэмплов): первые 45с после старта сборщика или пропуск внутри минуты |
| `STALE` | на ЭТОМ такте от биржи (см. `missing_now`) не пришло свежей цены — взято среднее из окна |
| `MISSING_EXCHANGE` | биржа выпала из окна целиком → веса перенормированы, индекс отклоняется от методики |

Каждая биржа опрашивается с ретраями (до 3 попыток в такте), поэтому `STALE`/`MISSING_EXCHANGE`
на стабильном сервере — редкость. Для строгой сверки с методикой фильтруй `flag == "ok"`.

## GET `{BASE}/api/stats`
Покрытие и параметры — для мониторинга/проверки живости.
```json
{
  "ticks_rows": 40, "index_rows": 10,
  "first_ts": 1785242655, "first_iso": "2026-07-28T12:44:15Z",
  "last_ts": 1785242670,  "last_iso": "2026-07-28T12:44:30Z",
  "coins": ["BTC","ETH","SOL","TRX","XRP"],
  "exchanges": ["binance","bybit","okx","bitget"],
  "weights": {"binance":0.5,"bybit":0.2,"okx":0.15,"bitget":0.15},
  "poll_sec": 15, "window_sec": 60
}
```
Живость: `last_ts` должен отставать от текущего времени не больше чем на ~15–20с.

## GET `{BASE}/api/index.csv`
Посчитанный индекс + минутные средние по биржам за диапазон. Отдаётся потоково.

**Параметры (query, все опциональны):**
| Параметр | Формат | По умолчанию |
|---|---|---|
| `coin` | `BTC`/`ETH`/`SOL`/`TRX`/`XRP` | все монеты |
| `from` | ISO8601 (`2026-07-28T00:00:00Z`) или unix-секунды | `to` минус **24 часа** |
| `to`   | то же | текущий момент |

**Колонки CSV:** `ts, iso_utc, coin, binance, bybit, okx, bitget, index_value, n_exchanges, min_samples, missing_now, flag`
```
ts,iso_utc,coin,binance,bybit,okx,bitget,index_value,n_exchanges,min_samples,missing_now,flag
1785242670,2026-07-28T12:44:30Z,BTC,63470.255,63468.9,63470.3,63472.205,63470.28325,4,4,,ok
```
Последние три колонки — контроль качества (легенда `flag` — в разделе `/api/latest`).
`missing_now` — список бирж через запятую (пусто = все пришли).

## GET `{BASE}/api/ticks.csv`
**Сырые** 15-секундные цены (каждая цена с каждой биржи) — для полной перепроверки.
Те же параметры, что у `index.csv`, но `from` по умолчанию — **1 час** (данных много).

**Колонки CSV:** `ts, iso_utc, exchange, coin, price`
```
ts,iso_utc,exchange,coin,price
1785242670,2026-07-28T12:44:30Z,binance,BTC,63470.26
```

## GET `{BASE}/api/db`
Консистентный снимок **всей** базы SQLite (через `VACUUM INTO`) — скачать и проверить
всё офлайн. Возвращает файл `index_snapshot.db` (`application/octet-stream`). Таблицы
внутри: `ticks` (сырьё) и `index_values` (индекс + биржевые средние).

## Как считается индекс (для сверки формулы)
На каждом такте `T` (кратном 15с):
1. по каждой бирже берётся среднее её цен за окно `(T-60, T]` (последние ≤4 сэмпла);
2. индекс монеты = `Σ(вес_биржи × среднее_биржи) / Σ(вес_биржи)` по биржам, где данные есть.

Пример (BTC): `63470.255·0.5 + 63468.9·0.2 + 63470.3·0.15 + 63472.205·0.15 = 63470.28325`.
При выпадении биржи её вес исключается, знаменатель = сумма весов оставшихся (перенормировка).
