# Криптоиндекс MOEX — пакет для интеграции в трекер

Сервис, который непрерывно реплицирует методику расчёта криптоиндекса MOEX и отдаёт данные
для новой вкладки в трекере `http://176.12.70.128`.

## Что делает
Раз в **15 секунд** (выровнено по стенным часам) одновременно опрашивает **4 биржи**
— Binance, Bybit, OKX, Bitget — по **5 монетам** (BTC, ETH, SOL, TRX, XRP, спот к USDT).
Каждая сырая цена сохраняется в SQLite. На каждом такте считается индекс:

1. по каждой бирже — среднее её цен за последнюю минуту (окно 60с, ≤4 сэмпла);
2. индекс монеты = взвешенное среднее биржевых средних, веса:
   **Binance 50% · Bybit 20% · OKX 15% · Bitget 15%**;
3. если биржа не ответила — её вес исключается, веса остальных перенормируются к 1.

Наружу — JSON/CSV API и снимок всей базы (для перепроверки). Сырьё хранится **всегда**.

**Надёжность данных.** Каждая биржа опрашивается с ретраями (до 3 попыток в такте, раздельные
таймауты на соединение). Качество каждого такта помечается флагом `flag` (`ok` / `PARTIAL_WINDOW`
/ `STALE` / `MISSING_EXCHANGE`) плюс `min_samples` и `missing_now` — чтобы **ни один пропуск в
сырье не остался незамеченным**: если на такте не пришла цена с биржи, индекс за этот такт помечен
как отклонение от методики. Легенда флагов — в `API.md`.

## С чего начать (для того, кто ставит)
1. **`INTEGRATION.md`** — пошаговая установка на сервер + добавление вкладки. Главный документ.
2. **`API.md`** — контракт эндпоинтов (что фронт вкладки дёргает).
3. Код: `index_core.py` (ядро), `app.py` (сервис с API), `collector.py` (только сборщик).

Два сценария подключения (подробно в `INTEGRATION.md`):
- **A** — поднять отдельный сервис `app.py` (сборщик+API) и проксировать подпуть `/crypto-index/`;
- **B** — гонять только `collector.py`, а данные отдавать роутами самого трекера (он на Python).

Рекомендуется **A** — не трогает код трекера.

## Состав пакета
| Файл | Назначение |
|---|---|
| `index_core.py` | конфиг, фетчеры бирж, SQLite, цикл сборщика, функции чтения |
| `app.py` | FastAPI: сборщик + API + служебный дашборд (сценарий A) |
| `collector.py` | автономный сборщик без API (сценарий B) |
| `requirements.txt` | зависимости (httpx; +fastapi, uvicorn для A) |
| `systemd/crypto-index.service` | автозапуск сервиса (A) |
| `systemd/crypto-index-collector.service` | автозапуск сборщика (B) |
| `frontend/tab-example.html` | референс вкладки: fetch API → карточки + выгрузка CSV |
| `API.md` / `INTEGRATION.md` | контракт API / инструкция по установке |

## Требования
Python **3.10+** на сервере. Никаких ключей бирж не нужно (все эндпоинты публичные).
Нагрузка на лимиты бирж ничтожна: 1 запрос на биржу раз в 15с.

## Важно: методические допущения
Формула расчёта заложена по описанию методики, но **сверьте с оригиналом MOEX**: цена =
last trade (не mid по стакану); обработка пропуска биржи = перенормировка весов; шаг 15с /
окно 60с; пары к USDT (пересчёт в RUB — отдельный слой). Всё это — константы в шапке
`index_core.py`, правится в одну строку. Подробнее — раздел 7 в `INTEGRATION.md`.
